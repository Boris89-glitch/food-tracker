# Food Tracker — setup & deploy

The app is a **React + Vite + Tailwind** Progressive Web App (PWA) that uses
**Firebase** for Google login, per-user cloud storage, and hosting. Follow the
one-time steps below to make it live; after that, every push to `master`
deploys automatically via GitHub Actions. Everything here is free at this scale.

> Until you paste your Firebase config (Step 3), the app runs in
> **local-only mode** (data stays on the one device, no login). Fill in the
> config to unlock Google sign-in + cross-device sync.

## Local development

```bash
npm install
npm run dev       # dev server with hot reload at http://localhost:5173
npm run build     # production build → dist/
```

## One-time setup

### 1. Create a Firebase project

1. Go to <https://console.firebase.google.com> and click **Add project**.
2. Name it (e.g. `food-tracker`), accept defaults, create it.

### 2. Enable the two services

**Authentication**
1. Left menu → **Build → Authentication → Get started**.
2. **Sign-in method** tab → **Google** → enable → pick a support email → **Save**.

**Cloud Firestore**
1. Left menu → **Build → Firestore Database → Create database**.
2. Start in **production mode** (our `firestore.rules` locks it down properly).
3. Pick a location close to you → **Enable**.

### 3. Add a Web app & copy the config

1. Project **Overview** (gear icon) → **Project settings** → scroll to **Your apps**.
2. Click the **web** icon `</>`, give it a nickname, **Register app**.
3. Copy the `firebaseConfig = { ... }` object it shows you.
4. Open [`src/firebase.js`](src/firebase.js) and replace the `PASTE_...`
   placeholders with your real values.

> These keys are **safe to commit publicly** — Firebase web API keys just identify
> the project. Actual security comes from the login + `firestore.rules`.

### 4. Install the Firebase CLI & log in

```bash
npm install -g firebase-tools
firebase login
```

### 5. Point this folder at your project

From the `food_tracker` folder:

```bash
firebase use --add        # pick the project you created, alias it "default"
```

This creates a `.firebaserc` file (safe to commit).

### 6. First deploy (manual)

```bash
npm run build
firebase deploy --only firestore:rules,hosting
```

You'll get a live URL like `https://food-tracker-xxxx.web.app`. Open it, click
**Continue with Google**, and you're in. Log in on your phone with the same
Google account → same data.

### 7. Connect GitHub for automatic deploys

```bash
firebase init hosting:github
```

Answer the prompts:
- Repository: `Boris89-glitch/food-tracker`
- Set up automatic deployment on merge? **Yes**
- Build script: `npm ci && npm run build`
- When it offers to overwrite the existing workflow files in
  `.github/workflows/`, say **Yes** — it fills in the real project id and
  creates the `FIREBASE_SERVICE_ACCOUNT_...` secret in the GitHub repo for you.

From now on:
- **Push to `master`** → GitHub Actions builds and deploys to the live site.
- **Open a pull request** → it builds and posts a temporary preview URL as a
  PR comment.

> Note: Firestore **rules** are only deployed by the manual command in step 6.
> If you ever change `firestore.rules`, run
> `firebase deploy --only firestore:rules` again.

### 8. Add to your phone's home screen

- **Android (Chrome/Brave):** open the URL → menu (⋮) → **Install app** / **Add to Home screen**.
- **iPhone (Safari):** open the URL → Share → **Add to Home Screen**.

It launches full-screen with its own icon — no address bar.

## Data model

Each signed-in user has one Firestore document at `users/{uid}`:

```
{ foods: [...], logs: {date: [entries]}, goal: 2000, weight: {date: kg}, unit: "kg" }
```

Writes are debounced and mirrored to `localStorage`, so the app is instant and
works offline; Firestore syncs the moment you're back online. The service
worker (generated by `vite-plugin-pwa`) caches the app shell for offline use
and updates itself automatically after each deploy.
